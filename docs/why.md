# 为什么做潘一琪 CLAW

## 1. 能力会变强，门槛不会自动下降

模型每半年更强一次。但一个只会跟豆包聊天的人，面对 Agent 仍然不知道：

- 什么是 prompt、上下文、工具、知识库；
- 该点哪里、填什么、怎么判断它做完了没有；
- 出了错怎么回滚、怎么让它重做。

能力提升只会让“本来就会用的那 1%”更强，不会自动让剩下的人用上。
**模型换代解决的是上限，产品要解决的是门槛。**

## 2. 我们要服务的人

不是 prompt 工程师，不是开发者，是：

- 每天用微信 / 豆包聊天，但没写过 prompt 的人；
- 工作被琐事填满、下班还在回消息的人；
- 只会说“帮我弄一下”，说不出字段、接口、验收标准的人；
- 想用 AI，但怕它乱动文件、乱发消息、乱花钱的人。

对他们来说，门槛不是“模型够不够聪明”，而是四件事：

1. 要不要学一套新词；
2. 要不要配置环境 / 填参数；
3. 做完的结果对不对，谁来判；
4. 敢不敢让它动真东西。

这四件事，才是 Agent 真正的“最后一公里”。

## 3. 产品判断：从“会用”到“敢用、用得上”

- **一句话开始**：不需要选模型、配 API、写 prompt；说清要做什么就行。
- **默认替用户做**：能自己决定的不问；必须问的一次只问一个真正阻塞的问题。
- **做完要能验收**：给结果、给证据、给回滚，不让用户猜“它到底做完没有”。
- **不陪聊**：聊天是入口，不是目的；目标是把工作接过去，而不是让用户跟模型谈恋爱。
- **失败要诚实**：没做完就说没做完，不把半成品包装成完成品。
- **默认安全**：能机器判的先判（文件、权限、越权、类型），危险动作先拦。

## 4. 成功指标

不是 benchmark 分数，而是：

- 一个原来不会用 Agent 的人，多久完成第一个真实任务；
- 每周因此省下多少分钟；
- 返工 / 求助 / “你帮我看看”的次数有没有下降；
- 他敢把多少真实工作交给它，而不是只拿它闲聊；
- 下班后，是否真的不用再被工作牵着走。

如果一个人用完之后，只是多了一个更聪明的聊天对象，那这个产品就失败了。
如果他用完，**真的少加了一小时班、少改了三版文案、少漏了一个客户**，才算成立。

## 5. 边界：不争“通用基建”

WorkBuddy 的通用基建（多租户、可观测性、部署、生态、IDE/插件、企业管控）比我们成熟，这是事实。
我们不在“平台广度”上争，我们争的是：

> **把一个已经存在的能力，翻译成普通人当天就能用、敢用、用完能验收的工作流。**

这也是为什么这个仓库开源的是“三负重轮 + 门禁”：
它们不是更聪明的模型，而是把“做完”和“做对”变成结构保证，
让不会判断结果的人，也能得到一个可验收的结果。
