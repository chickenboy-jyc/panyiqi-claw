# 案例：同样 DeepSeek V4 Flash，为什么普通人能用起来

先说边界：**这不是“潘一琪整体比 WorkBuddy 强”**。
WorkBuddy 的通用基建（多租户、可观测性、部署、生态、IDE/插件、企业管控）比我们成熟，这是事实。
下面两个案例只说明一件事：

> 在“同一个模型、同一个知识库、同一个 bug”的最后一公里，
> **把问题交给门禁和状态机，比让用户自己学 prompt、自己判断结果更快。**

两个案例都满足三个前提：

- 模型相同：DeepSeek V4 Flash；
- 不做微调；
- 不换知识库，只改编排层和判据。

## 先把“门槛账”算清楚

同样一个问题，普通用户在不同产品里要付出的东西完全不同：

| 环节 | 通用助手的常见路径 | 潘一琪要做的 |
|---|---|---|
| 问法不对 | 用户自己换个说法再试，试到命中为止 | 系统做同义词/动作/场景归一化，用户不用学 prompt |
| 结果对不对 | 用户自己读一遍、自己判断 | 机器门禁先判，再给证据 |
| 出了问题 | 用户把现象描述给 AI，AI 再猜 | 请求/输入可重放，差分直接指出哪一步错 |
| 配置 | 选模型、填 Key、配知识库 | 一句话开始，默认值可用 |
| 敢不敢用 | 怕它乱动文件/乱发消息 | 默认安全 + 可回滚 + 危险动作先拦 |

**能力提升解决上限，门槛下降解决“用不用得上”。** 下面的案例都在算后一笔账。

---

## 案例一：AI 客服“换个说法就掉知识库”

### 现象

同一个问题，用户换一种问法，客服就答不上来：

| 用户问法 | 结果 |
|---|---|
| 种植牙术后多久可以刷牙 | ✅ 命中 |
| 种牙后能刷牙吗 | ✅ 命中（关键词刚好齐） |
| 昨天种的牙，今天能刷牙吗 | ❌ 未命中，转人工/答非所问 |
| 种完牙可以漱口吗 | ❌ 未命中 |
| 刚种完牙能吃火锅吗 | ❌ 未命中，或命中到“刷牙”文档 |

WorkBuddy 的典型处理方式是：**继续改 system prompt**——
“请理解用户同义表达”“请优先检索知识库”“不要答非所问”。
改完再试，原问法还是好的，换一种说法又掉。因为问题不在模型“理不理解”，
而在**检索层只做了字面匹配**：`种植牙`、`刷牙`、`多久` 三个词少一个就不召回。
模型再聪明，也拿不到没被召回的知识。

### 根因

1. **召回层是字面匹配**：同义词、口语、时间换说法都不认；
2. **意图分类不稳定**：同一意图换个说法，分类结果漂移；
3. **没有回归集**：每次只测“原问法”，永远发现不了“换个说法”；
4. **用 prompt 修检索**：模型被要求“自己想办法”，但它拿不到文档。

### 修法（潘一琪的做法）

不是换模型，也不是加 few-shot，而是在模型前面加一层**确定性的查询规范化**：

```text
用户原话
  → 同义词归一（种牙/种一颗牙/种的牙 → 种植牙）
  → 动作归一（漱口/清洁/刷 → 刷牙）
  → 场景归一（吃饭/火锅/喝热水 → 饮食）
  → 意图门（刷牙？肿胀？饮食？）
  → 多路召回 + 兜底（精确词 → 归一化词 → 意图）
  → 模型只负责“把召回结果说成人话”
```

然后加一道**换说法回归门禁**：

- 同一个问题准备 12 种问法；
- 每条都断言“必须命中同一篇文档”；
- 同时保留“naive 检索必须至少漏一条”的反控——证明这个 bug 是真的，不是门禁恒绿；
- 任何一条掉命中，门禁红，不允许发版。

本仓库里有一个**可复现实验**：

```bash
node examples/ai-cs-paraphrase/gate.mjs
```

同一批 12 条问法、同一份知识库、没有模型参与：

```text
naive 检索：8/12 命中
归一化检索：12/12 命中
```

这不是“模型变聪明了”，是**召回层不再依赖用户恰好用了哪几个词**。

### 为什么对普通用户更省事

| | 继续改 prompt | 加归一化 + 门禁 |
|---|---|---|
| 定位 | 靠模型自述“我理解了” | 直接看哪条问法没召回 |
| 修复 | 改一句话，可能修好一个问法、修坏另一个 | 改归一化表，一次覆盖一类问法 |
| 回归 | 没有，靠人再问一遍 | 12 条问法自动跑，掉一条就红 |
| 结果 | 同一个 bug 反复出现 | 修一次，门禁守住 |

**同样的 DeepSeek V4 Flash，换一种问法掉知识库，不是模型问题，是检索层没有门禁。**

## 案例二：漏洞定位——先证伪，再修

### 现象

一个知识库接口按 `kb_id` 取文档，前端只传当前知识库的 id，看起来没问题。
但接口本身没有校验“这个 kb 是否属于当前用户/租户”。
只要把请求里的 `kb_id` 换成另一个租户的 id，就能读到别人的文档。

这类问题 WorkBuddy 也能分析，但常见路径是：

1. 读代码；
2. 推测“这里可能没鉴权”；
3. 给出一段“建议加 tenant_id 校验”的文字；
4. 没有真实请求、没有复现、没有回归。

潘一琪的路径是**先证伪，再修**：

```text
列攻击面（所有带 id 的读写接口）
  → 构造两个租户的最小请求
  → 差分：A 的 token + B 的 kb_id
  → 看响应是 200 + B 的正文，还是 403/空
  → 拿到机器证据，才改代码
```

修法也不是“在 prompt 里写注意鉴权”，而是：

- 查询层强制 `tenant_id = current_tenant`；
- 越权返回 404（不泄露资源是否存在）；
- 加门禁：同一请求重放，断言必须 403/404；
- 加反控：把 `tenant_id` 过滤去掉，门禁必须变红；
- 把请求写进 `chain.txt`，以后每次发版都跑。

本仓库里有一个可复现的最小实验：

```bash
node examples/tenant-isolation/gate.mjs
```

同一份数据、同一个 `kb_id`：

```text
naive handler：A 能读到 B 的文档（越权）
fixed handler：A 读 B 返回 null（修复）
反控：把 tenant 比较去掉，fixed handler 也必须重新越权
```

### 为什么快

| | 通用 Agent 读代码 | 门禁式排查 |
|---|---|---|
| 证据 | “我觉得这里可能有问题” | 两个租户的真实请求 + 响应 |
| 定位 | 靠阅读顺序、靠猜 | 差分直接指出哪个 id 没校验 |
| 修复 | 给建议，等人改 | 改完立刻用同一请求验证 |
| 防回归 | 没有 | 请求进链，去掉校验就红 |

门禁的 `0 / 1 / 99` 在这里很关键：

- `0`：鉴权生效；
- `1`：真的越权了；
- `99`：请求没发出去/服务没起来——**这次读数作废**，不是“通过”。

没有 99，服务没起来会被当成“没越权”，这是最危险的一种假绿。

## 案例三：同一个 bug 不再反复出现

这两个案例的共同点不是“模型更强”，是**每次修复都留下一个可重放的判据**：

- 客服换说法 → 12 条问法回归集；
- 越权 → 一条跨租户请求；
- UI 按钮被裁 → 一条 DOM/尺寸断言；
- 颜色回绿 → 一条色值棘轮。

WorkBuddy 更像“一个很强的通用助手”：你问它，它帮你分析、给方案。
潘一琪更像“一个带门禁的修复工位”：**问题必须被复现、修复必须被机器验证、回归必须进链**。

---

## 诚实的边界：通用基建不如 WorkBuddy

| 维度 | 潘一琪 | WorkBuddy |
|---|---|---|
| 同模型下的确定性修复 | **强**：归一化 + 门禁 + 反控 | 通用推理强，最后一公里要用户自己补 |
| 漏洞定位 | **快**：先证伪、差分、请求重放 | 代码分析强，真实请求少 |
| 回归防反弹 | **强**：修复即门禁 | 依赖用户自己补测试 |
| 普通用户学习成本 | **低**：一句话开始，系统兜底 | 中：要会描述、会判断结果 |
| 陪聊 vs 干活 | 目标是把工作接过去 | 通用对话强，工作流要自己拼 |
| 多租户 / 权限体系 | 弱 | **强** |
| 可观测性 / 部署 / 运维 | 弱 | **强** |
| 生态 / IDE / 插件 | 弱 | **强** |
| 企业管控 / 合规 | 弱 | **强** |
| 通用任务广度 | 窄 | **宽** |

所以正确的结论不是“碾压”，而是：

> **在“已知问题、需要确定性修复、必须防回归、用户不会判断结果”的场景，潘一琪的门槛更低、闭环更快；
> 在“通用基建、平台能力、生态广度”上，WorkBuddy 更成熟。**

把这两类能力拼起来，才是完整的产品。
而潘一琪的选择很明确：**不跟 WorkBuddy 比平台广度，先把“普通人当天就能用、敢用、用完能验收”这件事做到。**

## 对产品的三条直接含义

1. **不把“用户不会写 prompt”当成用户的问题。**
   系统去做归一化、默认值、追问收敛，而不是让用户去学一套新语言。
2. **不把“能聊”当成果。**
   聊天只是入口；任务完成率、节省的时间、返工次数，才是产品指标。
3. **不把“模型能力”当护城河。**
   模型会换代，门槛不会自动下降。护城河是：默认安全、结果可验收、失败可回滚、修复能防回归。
